# 性能与实体显示排错

[简体中文](PERFORMANCE.md) | [English](PERFORMANCE.en.md)

0.30.12 包含以下代码优化。两端编译和安装包完整性检查通过；按玩家要求没有启动游戏，尚无优化前后 FPS 对照数据。

| 环节 | 本版处理 |
| --- | --- |
| 原生敌人发现 | 两轮分配数组的全场物理查询合并为一轮可复用缓冲区查询，普通发现间隔 0.15 秒；现有目标的位置、防护与船接触路径仍每 0.05 秒更新，攻击指定目标时立即重新发现 |
| 地形采样 | 同一轮采样复用碰撞过滤器，按碰撞体缓存组件排除结果，减少每个格子重复查找组件 |
| 场景、人物、菜单与 HUD 帧 | 优先检查最新文件，每次刷新最多上传一张有效纹理；保留完整帧尾和场景/会话校验 |
| 持续刷新的 HUD | 默认每 GUI 像素对应一个纹素，取代两倍宽高的超采样；同尺寸下 RGBA 像素数据量减少 75%，这不代表游戏 FPS 提升 75% |
| 私有 MC 后台 | 默认最多 30 FPS，视距 2 区块、模拟距离 5 区块，关闭其垂直同步；只作用于 HollowCraft 私有配置，空洞端帧率不受此上限约束 |
| 越界生物 | 延续远处实体暂停机制，避免对暂停实体重复纠正位置和速度 |
| 大场景通信 | 请求上限从 64 KiB 调至有界 1 MiB，避免扩展生物地形样本使连接断开 |

## 实体透明或不能放置

空洞主相机使用透视投影，不能直接用 `orthographicSize` 推算实际场景视野。本版用屏幕射线与人物平面求交，后端也会给异常视野数据使用有效回退值。实体渲染器自行初始化离屏相机，避免后台未画过普通世界画面时一直等待相机。

真实 MC 生物的客户端追踪包尚未到达时，使用同类型、同 NBT 的原版渲染副本；它不加入客户端世界、不运行第二套 AI，后续仍以真实实体为准。船和生物没有改成图标。生成蛋的初始空间探测与后续运动统一使用二维厚度；成功放置会正确返回成功。船仍需要约 1.4 格宽的空位，实体总数上限仍为每场景 160。

右键失败现在会显示具体原因并写入日志。更新后须先关闭两端，再通过原启动入口重启；运行中的旧 Java 进程不会自动加载新 JAR。生成蛋仍只在创造菜单提供。

## 仍有卡顿时

优先减少同一画面的大量召唤物、散落物、爆炸和流体更新，并在录制时使用 1280×720 的空洞窗口。不要同时另开一份桥接后台。无需盲目增大 Java 堆；本版没有把加内存当成通用修复。

排查所需文件为 `runtime/hollowcraft-hk.log` 与 `runtime/minecraft/logs/latest.log`。有用的记录包括 `Placed creature`、`Entity placement rejected`、`Native world entity frames ready`、`Native entity frame unavailable`、`Oversized message` 和 `Can't keep up`。说明当时区域、召唤物种类与大致数量，可区分生成失败、渲染失败和模拟负载。

源码开发者可用 JVM 参数 `-Dhollowcraft.backendFps=60` 提高后台上限，或 `-Dhollowcraft.hudScale=2` 恢复 HUD 超采样；默认值侧重降低双引擎资源竞争。这些参数不是必须的安装步骤。

## 后续优化方向

目前仍保留同步 GPU 回读与 RGBA 帧文件传输。下一步可对照实际耗时实现异步 GPU 回读、共享内存或更小的脏区域传输，再把高频实体显示逐步移入空洞本地。共享内存主要解决复制与文件传输成本，不会自动降低 MC AI 和 GPU 回读成本。

完全独立 Mod 需要复现原版模型、材质、动作、物品规则、AI 与存档兼容，属于持续迁移，不能靠删掉 MC 进程获得相同还原度。当前路线与边界见 [架构说明](ARCHITECTURE.md)。
