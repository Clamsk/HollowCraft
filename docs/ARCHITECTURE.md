# HollowCraft 的运行边界与独立 Mod 路线

[简体中文](ARCHITECTURE.md) | [English](ARCHITECTURE.en.md)

HollowCraft 是两个本地游戏进程间的桥接，运行通信为 localhost TCP。MCP 不在运行链路中，不处理每次鼠标点击。已发现的进食特殊路径、原生碰撞缺失、跳跃松键清零、文件替换失败及存档回包串用均属于本项目实现问题。

## 当前职责

| 空洞端直接处理 | MC 后端处理 |
| --- | --- |
| 窗口点击队列、准星、左右挥舞选择 | 攻击属性、武器配置、冷却、耐久、附魔 |
| 2D 移动、跳跃积分、真实地形碰撞 | 血量、饥饿、食物、护甲和状态效果 |
| 方块碰撞预生成与结果确认 | 方块放置规则、数量消耗、方块更新 |
| 投射物连续碰撞及安全落点 | 原版投射物伤害、投掷、药水和珍珠效果 |
| 原生 AI、剧情、命中反馈和地图物件 | 原版背包、配方、容器、熔炉与红石 |
| MC 风格 UI 的场景内显示 | MC 第三人称模型及 Better Combat 动画渲染 |

这样可以让即时操作靠近空洞物理帧，同时继续使用 MC 原版规则。人物目前由 MC 的真实第三人称渲染器画成带深度的透明帧；空洞显示整个人物帧。它还不是空洞内部的独立骨骼渲染器。

## 完全独立方案

只启动空洞的独立 Mod 技术上可行，但当前版本尚未实现。需要逐步补齐以下组件：

1. 本地骨骼、原版模型坐标和 UV、盔甲层、握持变换与动画混合，正确实现举盾、拉弓、双手武器、蹲姿和滑翔。
2. 原版物品定义、NBT、合成配方、容器规则、附魔、药水、战斗和生存数值，能够导入现有存档。
3. 本地方块状态、采掘、流体、光照、红石和实体系统，并处理与原生地图的交互。
4. 独立资源导入器，从用户合法安装提取所需模型和贴图；源码仓库不发布游戏素材。
5. 对照 MC 后端的行为记录和玩家反馈，逐项检验兼容性；保留可回退的原版后端，直到替代组件达到同等表现。

先将即时输入与碰撞迁入空洞端是可复用的一步；删除 MC 后端本身不会自动解决动画、配方或数值错误。当前保留桥接作为还原基准，未擅自将既有玩法换成大规模简化重写。

## 开发优先级

先修复玩家报告的进食、珍珠、创造菜单、跳搭和漏点击；随后处理存档隔离、传送及落地状态、容器交互、剧情与路线障碍。继续检查关键玩法之间的状态冲突，按版本编译和交付。玩家要求不自动启动游戏验收，因此版本说明必须区别“已编译”“实现调整”和“实机确认”。全流程通关不是编译成功即可证明的结果。

## 性能优化

0.30.12 减少重复物理发现扫描与纹理上传，给私有后台设置预算，并以原生像素尺寸传输 HUD。GPU 回读与跨进程 RGBA 传输仍有成本，后续需要继续改进，见 [性能与排错](PERFORMANCE.md)。
